I'm an Electronics & Communication Engineering student at **BIT Mesra**, working at the intersection of **applied AI, computer vision, software engineering, and mobile development**. I'm drawn to problems that require going all the way from raw signal/data to a system someone can actually use.

My approach to building something generally follows this loop:

```
Problem → Mathematical / Algorithmic Reasoning → Model / Algorithm
```

A few things that describe how I work:

- 🏗️ I care about the layer *between* the model and the user — the mobile app, the inference pipeline, the integration points — because a model that isn't usable isn't finished.

- 📊 I'd rather report an honest MAE/RMSE than an inflated claim — evaluation is part of the engineering, not an afterthought.
- 🔁 I'm still early in my career, but I build things end-to-end and iterate on them deliberately.

### 🩸 Project 1 — AI-Based Non-Invasive Anaemia Detection System
**Predicting haemoglobin-related severity from conjunctiva images using a hybrid feature pipeline and a Mixture-of-Experts framework.**

<details open>
<summary><b>📖 Full Technical Breakdown</b></summary>
<br/>

**Problem**
Anaemia screening traditionally requires invasive blood tests. This project explores whether a **non-invasive, image-based approach** using conjunctiva images can estimate anaemia severity.

**Pipeline**

```
Conjunctiva Image → Feature Extraction → Hybrid Feature Representation 
                  → PCA → Mixture-of-Experts → Probability-Based Fusion 
                  → Hb Prediction
```

**Approach**
- Built a **90-dimensional hybrid feature representation** per image, combining:
  - **18 handcrafted RGB / LAB / GLCM features**
  - **CNN embeddings** (deep visual features)
  - **2 demographic features**
- Reduced CNN feature dimensionality from **2048 → 300** using PCA to control redundancy before fusion.
- Designed a **Mixture-of-Experts framework** with **3 separate XGBoost regression heads**, each specialized for a class regime — **Normal / Mild / Severe** anaemia.
- Combined expert outputs using **probability-based weighted fusion** rather than a hard class switch, so the final prediction reflects the model's confidence across regimes.

**Why this architecture**
A single regressor struggles to fit well across very different severity regimes at once. Splitting the problem into class-conditioned experts, and letting a probability-weighted fusion combine them, let each expert specialize while still producing one continuous Hb estimate.

**Results**

| Metric | Value |
|---|---|
| MAE | ≈ 0.71 |
| RMSE | ≈ 0.95 |
| R² | ≈ 0.83 |

**Technical Summary**

| Component | Details |
|---|---|
| Domain | Healthcare AI / Computer Vision |
| Dataset | 710 conjunctiva images |
| Feature Representation | 90-dimensional hybrid features |
| Handcrafted Features | RGB / LAB / GLCM |
| Deep Features | CNN embeddings |
| Dimensionality Reduction | PCA: 2048 → 300 |
| Modeling | 3 XGBoost regression heads |
| Framework | Mixture-of-Experts |
| Fusion | Probability-based weighted fusion |
| MAE | ≈ 0.71 |
| RMSE | ≈ 0.95 |
| R² | ≈ 0.83 |

**Technologies:** `Python` `OpenCV` `TensorFlow` `Scikit-learn` `XGBoost` `PCA`

**A computer-vision-driven recommendation pipeline that maps detected facial emotion to music suggestions.**

<details>
<summary><b>📖 Full Technical Breakdown</b></summary>
<br/>

**Pipeline**

```
Camera / Image → OpenCV → DeepFace Emotion Recognition 
              → Mood Classification → Song Recommendation
```

**Approach**
- Used **OpenCV** for image/video capture and preprocessing.
- Applied **DeepFace** for facial emotion recognition to classify the detected mood.
- Mapped the recognized mood to a corresponding song recommendation through an automated recommendation pipeline, closing the loop from **camera input → inferred emotional state → music suggestion**.

**Engineering perspective**
